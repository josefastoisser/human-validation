Arrays are NumPy files without pickled objects. {part}_inputs.npz contains ids [N] and fields [N,5,3,113,32], with channels xi, theta, ustar in that order. train_targets.npz and validation_targets.npz contain the corresponding ids and xi [N,20,113,32]. train.csv, validation.csv and test.csv give window IDs, simulation_id, zero-based origin, u and alpha. All 25 frames in a case are consecutive. Inputs cover origin,...,origin+4 and targets cover origin+5,...,origin+24. Evaluation cases use nonoverlapping origins 0,25,50,75,100,125. Related windows must stay in one simulation partition. These cases come from labeled training simulations; they are a local evaluation, not Kaggle's official test set.

training_simulations/ contains complete 150-frame sequences for training simulations only. Each NPZ has fields [150,3,113,32] with channels xi, theta, ustar; simulations.csv supplies u and alpha. You may construct additional training windows inside these simulations. No complete validation or test flowfield files are provided. Validation targets are available for model selection. Test inputs contain exactly five frames in every case. No future theta/ustar is supplied for validation or test.

The binary source loader reads little-endian float32 and reshapes in C order as (Nt,Nx,Ny), verified against contemporary competition code. The prepared arrays use this layout without rotation, resizing, clipping, thresholding or target derivation. Xi is fire-line location; it is neither temperature nor accumulated burned area. The sample submission is an all-zero format template with no performance claim. Keep six-digit simulation filename IDs intact: e.g. 016525 is the string form of numeric ID 16525. Window IDs append _t followed by a three-digit origin. Do not infer labels from these identifiers.

Local output is the CSV contract in the task prompt. The final output always has 20 frames even if your model can forecast further. All conditions use identical public files and runtime budgets.
