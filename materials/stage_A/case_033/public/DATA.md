# Event-based pupil tracking inputs

All coordinates refer to the same sensor pose: x increases along the original sensor x axis, y along the original y axis. There is no flip, crop, registration or calibration. Original event and label coordinates are 640×480; output x and y are each divided by 8, giving 80×60. Coordinates are pupil centers in the sensor image, not angles or world-space gaze.

train.csv has the fitting rows; validation.csv provides labeled validation rows from separate subject groups. test.csv contains the required prediction rows. Columns row_id,recording_id,frame_index,label_index_100hz,timestamp_us,event_start_us,event_end_us,event_path,counts_path identify inputs. Labeled CSVs additionally contain x,y,close. close=0 means open and close=1 means blink. No close values are supplied for test. Blink frames are retained and scored using their recorded pupil coordinates; no mask, interpolation, last-open replacement or imputed labels is applied. No frame is excluded based on event count.

Event files in events/ are unmodified HDF5 recordings, with only the dataset events. Its structured fields t,x,y,p are little-endian uint64. t is microseconds, starts at zero, and is nondecreasing. x,y are original sensor pixels (640×480). p is stored as 0 or 1; mapping to signed polarity is 2*p-1. Load with h5py.File(path)['events'][:]. File paths are relative to data/. Raw training and validation annotations at 100 Hz are in labels100hz/; held-out annotations are absent.

For each recording, retain label lines 0,5,10,... from its original 100 Hz label file, exactly as the organizer's TemporalSubsample(0.2). At frame k, label_index_100hz=5*k and timestamp_us=50000*k. Label time denotes the start-aligned target used by the organizer pipeline; input frame k uses events in [50000*k,50000*(k+1)). Keep the last interval even if incomplete. Labels have no separately recorded timestamp column; this alignment follows the demo indexing convention. The streams start at t=0. Model windows may span frames within a recording, but must not cross recording boundaries.

counts/ contains a convenient deterministic 20 Hz count representation. np.load(path,allow_pickle=False)['counts'] has shape (number_of_frames,2,60,80), dtype little-endian uint32. The polarity axis uses raw p=0 then p=1. Event pixels are floor(x/8),floor(y/8); counts accumulate all events in the start-aligned half-open interval, without normalization. Events beyond the last labeled interval are not included in counts; raw HDF5 files retain them. This representation is supplied to keep modest CPU baselines feasible. Both raw inputs and counts are identical in all conditions; no model or metric-specific representation is supplied.

Frames are ordered by numeric recording tuple (first component, second component), then frame_index. row_id is a split-local sequential decimal integer beginning at zero. The exact test.csv row order defines submission order. All original publicly labeled recordings are assigned as complete subject groups to one of fitting, public validation, or test; neighboring frames and sessions of a subject are never split between these partitions. Only the official training-label pool is used. Original official test label_zeros.txt files are placeholders and are not references for this package. The package is a local labeled holdout benchmark, not the historical Kaggle leaderboard.

The public sample_submission.csv is a constant sensor-center format example (40,30). It is not a tracker. Grading uses IEEE binary64 coordinates and distances. Values must produce finite Euclidean distances; invalid artifacts have no numeric score. The radius boundary is strict. Metrics pool frames equally without dropping blinks or weighting activities. No separate activity labels were provided in the downloaded files; no activity classes have been inferred from session numbers.
